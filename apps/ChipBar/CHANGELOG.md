# 更新记录

## [Unreleased]

## [2.1.0] - 2026-10-26

- 修正 2.0.4 小卡片中环形跑道压缩 CPU/GPU 标题的问题：每张卡片改为左右两列，左侧依次显示名称、功率和温度，右侧圆环与指标列等高并独立占位，不再遮挡标题。
- CPU 与 GPU 圆环下方不再显示「占用」两字；ANE 的圆环仍保留「内存」标注，明确区分它显示的是系统内存占用，而不是 ANE 使用率。
- 将占用圆环直径由 42 pt 调整为 39 pt，保留数字弹簧动画、内存压力颜色与辅助功能提示；卡片采用 8 pt 统一内边距和一致的纵向基线，使三个小卡片更加紧凑。
- 沿用原有采样逻辑、功率趋势微型图和面板宽度，无需修改现有用户设置。


## [2.0.4] - 2026-10-25

- 将 CPU/GPU 占用率的环形跑道分别移入 CPU/GPU 功率卡右上角，将内存占用率环形跑道移入 ANE 功率卡右上角；删除原先独立的圆环行。
- 统一三张功率卡的上缘、圆环插槽、内边距及温度和功率趋势位置；缩小圆环至 42 pt、放大功率数字至 20 pt，并适当增加功率卡高度，使视觉中心更明确、整体面板更紧凑。
- 内存圆环继续根据真实内存压力着色，悬停和辅助功能中保留压力状态；沿用原有弹簧变化动画及「减少动态效果」兼容性，不更改功率或占用率采样算法。

## [2.0.3] - 2026-10-25

## [2.0.1] - 2026-10-25

## [2.0.0] - 2026-10-25

- 重构 370 pt Liquid Glass 监控面板：保持原有双排菜单栏和功率读数，统一按钮按压、页面切换及图表动画，降低采样刷新对窗口布局和触控板惯性滚动的干扰；每次打开恢复主页初始状态。
- 主面板以 CPU/GPU/ANE 功率、温度和微型趋势、CPU/GPU/内存占用圆环、逐逻辑核心 CPU 占用柱图、应用资源排行及精简功率趋势为主；圆环缩小至 52 pt，趋势图缩小至 64 pt。
- **内存状态合并到占用圆环**：圆环数字显示系统内存已用百分比，底部显示已用／总量；环形跑道的颜色直接取自系统内存压力（正常绿色、偏高黄色、紧张红色、未知中性色），不因已用百分比高就误报内存压力。删除下方重复内存行和原独立三色压力指示。
- 使用 Mach `host_processor_info` 的逐逻辑核心 CPU 时间差计算占用；按所选刷新率低频更新，只在主面板可见且未暂停时采集，无管理员权限或额外命令依赖；不会将逻辑核心序号臆断为 P/E 核类型。
- 应用占用可切换 CPU、GPU、内存和 ANE；保留应用图标、名称与准确的资源值。切换时旧列表缩小渐隐、新列表从上方叠入，尊重「减少动态效果」；移除应用占用条以减轻视觉拥挤。
- 首页「储存空间」统一展示内置储存和已挂载外接盘的可用、已用、总容量及占用进度条；外接容量不依赖 SMART，区分内置和外接设备，不累加 APFS 共享容量。
- 合并「系统详情」和「设置」为「设备与设置」二级页面，显示 Mac 型号标识、芯片、macOS 版本、物理内存、逻辑核心数，以及风扇、SSD 温度／I/O／SMART 和原有菜单栏偏好设置；统一 AppKit/SwiftUI 外观，刷新频率使用纯 SwiftUI 分段选择器，改善深浅模式初次绘制闪烁。
- 优化可见性驱动的采样、慢速磁盘容量缓存、AppKit 窗口布局合并调度与二级页面固定窗口高度；补充逐核心采样、APFS 容量、内存压力颜色、布局尺寸和面板返回状态等自动化回归测试。
- 保持 macOS 13+ / Apple Silicon 与已有 macmon 依赖；仍需在不同设备与高刷新率显示器上进一步实测动画表现。GitHub 安装包为本地签名、未公证，可能触发 macOS 安全确认。


## [1.3.17] - 2026-10-24

- 主面板新增「内置储存」卡片，显示内置启动盘可用容量、已使用容量、总容量及占用进度；保留紧凑 Liquid Glass 设计及原有外接 NVMe SSD 区域。
- 优先读取系统 APFS Data 卷，使用 Disk Arbitration 确认磁盘为内置设备，不累加共享 APFS 容器的多个卷，不把外接或网络盘误报为内置。
- 每 30 秒异步读取一次容量；无 sudo、无新增外部依赖。读取前后卡片保持同高以避免面板高度跳动，尊重减少动态效果；缺失信息如实显示不可用。

## [1.3.16] - 2026-10-24

- 应用内存排行统一使用经过数量级检查的字节值与 MB/GB 格式化逻辑，避免异常微小的计数器结果被呈现为 0.0 KB；ANE、CPU、GPU 的展示逻辑保持不变。
- `--diagnose-apps` 新增每个应用的原始内存字节数、显示值、进程数量和 RSS 近似来源，以及可读取进程数和内存最小/最大值，便于与 macOS 活动监视器逐项对照。
- 增加 Chrome 和 ChatGPT 类似的多进程内存汇总及单位格式化回归测试。已在 M5 Pro 诊断测试版验证 Chrome 与 ChatGPT 能显示数 GB 数值；图标、菜单栏和 Liquid Glass 布局均不变。

## [1.3.15] - 2026-10-24

- 修复 M5 Pro 上「应用占用 → 内存」仍显示 0.0 KB 的问题：macOS 内存字段可能返回异常微小但大于零的读数，旧代码只检查是否大于零，因此跳过了 RSS 后备方案。
- 将小于 64 KiB 的进程物理足迹视为不可信数值，继续尝试 V4 读取；仍异常时使用 `PROC_PIDTASKINFO` 的 RSS，并标记 `≈`。若所有方法不可用则不编造数据。
- 增加 1 字节及极小读数回归测试、当前进程真实 V6 读取测试，以及所有已读取应用内存的最小合理性断言。保留原有图标、菜单栏、应用排行与刷新策略。

## [1.3.14] - 2026-10-24

- 修复「应用占用 → 内存」全部显示 0.0 MB 的问题：不再把成功但返回零的 `ri_phys_footprint` 当成有效值，依次尝试兼容的 V4 物理足迹与 `proc_pidinfo(PROC_PIDTASKINFO)` 的驻留内存 RSS 备选。
- RSS 与活动监视器所用物理足迹含义不同；采用 RSS 的应用在内存排行中以 `≈` 标记，说明和进程可读取计数同步标注近似来源。
- 不可用的内存读数保留为空，避免错误的 0.0 MB；小于 1 MB 的有效读数改为 KB 显示，保留原来的应用/辅助进程聚合与采样间隔。
- 增加 macOS 真实进程内存读取回归测试，确保自进程和进程列表能读取非零数据，并覆盖零值拒绝、权限缺失、RSS 近似来源和应用合并。

## [1.3.13] - 2026-10-24
