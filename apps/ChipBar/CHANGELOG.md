# 更新记录

## [1.3.15] - 2026-10-24

- 修复 M5 Pro 上「应用占用 → 内存」仍显示 0.0 KB 的问题：macOS 内存字段可能返回异常微小但大于零的读数，旧代码只检查是否大于零，因此跳过了 RSS 后备方案。
- 将小于 64 KiB 的进程物理足迹视为不可信数值，继续尝试 V4 读取；仍异常时使用 `PROC_PIDTASKINFO` 的 RSS，并标记 `≈`。若所有方法不可用则不编造数据。
- 增加 1 字节及极小读数回归测试、当前进程真实 V6 读取测试，以及所有已读取应用内存的最小合理性断言。保留原有图标、菜单栏、应用排行与刷新策略。

## [1.3.14] - 2026-10-24

- 修复「应用占用 → 内存」全部显示 0.0 MB 的问题：不再把成功但返回零的 `ri_phys_footprint` 当成有效值，依次尝试兼容的 V4 物理足迹与 `proc_pidinfo(PROC_PIDTASKINFO)` 的驻留内存 RSS 备选。
- RSS 与活动监视器所用物理足迹含义不同；采用 RSS 的应用在内存排行中以 `≈` 标记，说明和进程可读取计数同步标注近似来源。
- 不可用的内存读数保留为空，避免错误的 0.0 MB；小于 1 MB 的有效读数改为 KB 显示，保留原来的应用/辅助进程聚合与采样间隔。
- 增加 macOS 真实进程内存读取回归测试，确保自进程和进程列表能读取非零数据，并覆盖零值拒绝、权限缺失、RSS 近似来源和应用合并。

## [1.3.13] - 2026-10-24

- 「应用占用」增加内存排行，资源选择调整为 CPU / GPU / 内存 / ANE 四项，保留现有前三名及展开前五名的紧凑布局，不改变 370 pt 面板宽度。
- 使用 macOS 既有进程采样中的 `ri_phys_footprint` 获取当前应用内存占用，按同一应用的可读取辅助进程合计，以 MB 或 GB 显示；数据不可读取时不伪造读数。
- 内存与 ANE 单独记账的神经网络内存分开显示，补充各指标说明和采样状态；增加应用分组、当前读数更新、读取缺失及数值溢出的单元测试。
- 沿用现有 2 秒以上的应用资源轮询及 10 秒缓存策略，不增加额外进程扫描；应用图标保持不变。

## [1.3.12] - 2026-10-24
